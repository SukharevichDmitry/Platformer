# Constrained world generation plan

- [x] **1. Define and validate generation profiles.** Add a data format for location room-count ranges, allowed enemy types, and weighted room patterns with size, form, and spawn ranges. Reject empty, contradictory, duplicate, or unsupported rules before generation starts. Keep the current authored locations playable. **Done:** `assets/generation/ruins.json` loads through `GenerationProfile`; `core:check` passes valid and malformed profile checks alongside the existing authored-room checks.
- [x] **2. Define reusable room templates and story anchors.** Tag authored templates with pattern, doorway positions, entry/exit role, biome, encounter role, and narrative event IDs. Reserve mandatory start, landmark, story, and exit rooms; allow optional rooms around them. **Done:** `assets/generation/ruins.templates.json` contains four ordered story anchors, two optional branch choices, and two reusable route fillers; `RoomTemplateCatalog` validates geometry, profile limits, narrative IDs, and free doorway sockets in `core:check`.
- [x] **3. Generate a seeded room graph.** Choose a room count within the profile range; place required anchors in order; add weighted traversal/combat/branch rooms under per-pattern quotas. Use stable room IDs and a stored seed. **Done:** `RoomGraphGenerator` builds reciprocal, connected room links with 5–10 rooms, ordered story anchors, optional branches, and profile quotas. `GeneratedRoomGraph` carries the seed and stable per-seed IDs; `core:check` verifies 1,000 seeds and repeatability. Coordinates and tile joins remain point 4.
- [x] **4. Place rooms and join doorways.** Select template dimensions within their allowed ranges, lay out the graph without overlap, align reciprocal doors, and keep floor height and entry clearance consistent across seams. **Done:** `RoomLayoutPlacer` places seeded graphs without overlap, expands optional rooms within pattern limits, aligns reciprocal openings, seals unused sockets, and preserves continuous walking-level floors across horizontal seams. `core:check` verifies 1,000 seeds and rejects mismatched doorway spans. Hero movement reachability through all openings is checked in point 5.
- [x] **5. Vary tiles inside patterns.** Assemble supported floors, platforms, and cover from bounded pattern pieces rather than independent random tiles. Preserve a guaranteed path from every entrance to every required exit using the hero's actual movement limits. Add hazards and decoration when their tile behavior exists. **Done:** `RoomTileGenerator` adds seeded 2–4 tile platform pieces and short solid cover pieces above a protected walking corridor. The optional branch now uses an entry-room side doorway at floor height because the previous ceiling doorway exceeded the hero's jump reach. `RoomRouteReachability` checks the hero's size, clear standing lane, continuous floor, and each joined doorway; `core:check` verifies 1,000 seeds, repeatability, tile variation, and rejection of blocked routes. The current tile system has no hazard or decoration behavior, so generation emits neither until those tile types exist.
- [x] **6. Generate encounters under location and room rules.** Register enemy type IDs, choose only types allowed by the location and selected pattern, obey spawn count and difficulty budgets, and reserve clear safe space around entries and story interactions. Add `enemy1` and `enemy2` definitions before a profile requests those IDs. **Done:** `RoomEncounterGenerator` produces deterministic room-local spawns after tile generation; `EnemyFactory` exposes the supported types, body sizes, and difficulty costs; the ruins profile caps room and location difficulty. Safe rooms remain empty, the exit has one boss, and the validator rejects unsupported types, blocked terrain, overlaps, unsafe entry/story space, and budget violations. `core:check` verifies 1,000 seeds. `enemy1` and `enemy2` remain unsupported and are not requested by the profile.
- [x] **7. Integrate generation with loading and transitions.** Let `RoomManager` load either authored data or a generated location through the same `LocationInstance`/physics/render path. Generate once per run or visit policy, never during an active physics step; use a validated fallback if a seed cannot satisfy constraints. **Done:** forest's right edge opens into seeded ruins; the leftmost generated room has a return opening to forest, including runs with an optional left branch. `RoomManager` keeps one generated location per run, and generation runs before the old location is unloaded and outside a locked physics step. A failed seed retries validated seed 0. The packaged `generatedLocationTest` crosses both borders and repeats load/unload 20 times with stable body and enemy counts.
- [x] **8. Persist the generated run.** Save profile version, seed, room graph/layout, narrative choices, and stable entity state. Restore the same world and defeated enemies after a reload. **Done:** the generated run is stored as versioned JSON in libGDX Preferences with the profile version, seed, topology and placement signatures, ordered narrative choices, and stable defeated-spawn IDs. Loading regenerates from the saved seed and verifies the saved signatures; incompatible or malformed records are discarded. Defeated generated enemies are skipped when ruins are revisited or the game is restarted. The packaged `generatedRunPersistenceTest` verifies a complete save/reload round trip with identical room positions and exits and one defeated enemy still absent.
- [x] **9. Add quality gates and tuning tools.** Run many deterministic seeds through schema, connectivity, doorway, jump/reachability, collision, spawn, and transition checks. Log the failing seed and rule; add an in-game/debug seed display and a simple profile statistics report. **Done when:** automated seeds pass and failures are reproducible from one seed.
- [x] **10. Playtest and tune the mix.** Compare generated routes against authored narrative pacing, adjust weights and quotas, and lock the first production profiles after playtests. **Done:** ruins profile version 2 is marked production and raises the arena weight from 2 to 3 so longer routes contain fewer consecutive safe passages. The 5,000-seed gate locks average route length, enemy density, combat-room share, and optional-branch frequency while the required arrival, bell, shrine, and exit story sequence remains fixed. Single-seed runs remain available for manual playtest reproduction.

- [ ] **Design constraints to preserve throughout:** authored story rooms remain mandatory; all random choices use a recorded seed; profile ranges are hard limits; generation never emits unsupported enemies or unplayable entrances; content files remain validated before physics bodies are built.
